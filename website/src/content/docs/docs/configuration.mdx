---
title: "sqlload.toml"
description: "Every key of a loader project's sqlload.toml: connections, targets, sources and table settings."
---

`sqlload.toml` is a loader project's configuration. `sqlload` reads it from the working directory,
or from `-c`/`--config` or `SQLLOAD_CONFIG`. Unknown keys are errors. See
[Projects](/docs/concepts/projects/) for how the parts fit together.

`${ENV:NAME}` anywhere in the file is replaced with the environment variable `NAME`; an unset
variable is an error. `$${` is a literal `${`.

The [Kafka exporter](/docs/kafka/) uses a different file format.

## Top level

| Key | Default | Meaning |
|-----|---------|---------|
| `python_paths` | none | Folders, relative to the file, scanned for Python sources. |
| `default_target` | none | The target for sources that name no `destination`. Not needed with one target. |
| `concurrency` | 4 | The most tables loading at once. `--concurrency` overrides it. |
| `[connections.NAME]` | | How to reach a system. |
| `[targets.NAME]` | | Where loaded tables go. |
| `[sources.NAME]` | | Where data comes from. |

### `s3`

| Key | Meaning |
|-----|---------|
| `bucket` | The bucket. |
| `region` | The bucket's region. |
| `endpoint` | A custom S3-compatible endpoint. |
| `profile` | From 0.27.0. The profile of the AWS shared credentials file to take keys from. Default: `AWS_PROFILE`, else `default`. |

SQLLoad takes the first credentials it finds, in this order:

1. `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` (with `AWS_SESSION_TOKEN`) in the environment.
2. From 0.27.0, keys in the shared credentials file (`AWS_SHARED_CREDENTIALS_FILE`,
   default `~/.aws/credentials`), under the connection's `profile`, else `AWS_PROFILE`, else
   `default`.
3. Web identity.
4. The instance or container role.

From 0.27.0, a profile you name, with `profile` or `AWS_PROFILE`, must have
`aws_access_key_id` and `aws_secret_access_key` in that file; otherwise the connection fails rather
than trying the next source. SSO, assumed roles and `credential_process` in `~/.aws/config` aren't
read. Also from 0.27.0, `sqlload debug` shows where each S3 connection's keys come from, never the
keys.

SQLLoad removes files in bulk, up to 1,000 per request. For an S3-compatible store without bulk
delete, set `AWS_DISABLE_BULK_DELETE=true`: SQLLoad then deletes each file with its own request.

| Key | Applies to | Meaning |
|-----|------------|---------|
| `connection` | all | A `snowflake`, `databricks`, `bigquery`, `clickhouse`, `postgres`, `duckdb`, `s3` or `filesystem` connection, or from 0.33.0 a `motherduck` connection. |
| `loader_schema` | warehouses, required | The schema for tables whose source sets no `schema`; a BigQuery target's dataset, a ClickHouse target's database. |
| `database` | warehouses except ClickHouse | Overrides the connection's database. |
| `path` | files | Each table's folder template, with `{source}`, `{schema}`, `{table}`, `{cursor}` and `{cursor:date}`. Default `{source}/{table}/`. |
| `format` | files | `parquet` (default), or from 0.27.0 `csv`. |
| `compression` | files, csv | From 0.27.0. `none` (default), `gzip` or `zstd`. |
| `csv` | files, csv | From 0.27.0. `{ delimiter, header, quote, null_value }`; default `,`, `true`, `"` and an empty string. |
| `single_file` | files | From 0.27.0. One file per table or partition, named after the table folder. Default `false`. |
| `max_footer_reads` | files | The most Parquet footers `plan` reads for one table's schema. Default 100. |
| `naming` | warehouses | `snake_case` (default) or `source`: the case of table and column names. A source or table may override it. See [Naming](/docs/concepts/nested-data/#naming). |
| `compat` | warehouses | From 0.53.0. `sqlload` (default) or `dlt`: the names of the columns a load adds and of the child tables `unnest` makes. A source or table may override it. See [compat](/docs/concepts/nested-data/#compat). |
| `send` | warehouses | From 0.53.0. `at_commit` or `per_batch`: whether each commit's rows wait locally and reach the target in one burst at the commit, or each batch goes as it's read. Default `at_commit` on Snowflake, Databricks and MotherDuck, `per_batch` elsewhere. A source or table may override it. See [Sending rows at commit](/docs/targets/#sending-rows-at-commit). |
| `staging_dir` | warehouses | From 0.53.0. The folder `send = "at_commit"` holds rows in until their commit. Default: the system's temporary folder. |
| `json_type` | DuckDB, MotherDuck | From 0.54.0. `json` (default) or `variant`: whether `json` columns are DuckDB `JSON` or `VARIANT`. See [VARIANT columns](/docs/targets/duckdb/#variant-columns). |

| `new_tables` | postgres | `sync` (default), `skip` or `fail`. See [Sources](/docs/sources/postgres/#choosing-tables). |
| `cdc_mode`, `slot`, `publication`, `batch_interval` | postgres_cdc | See [Postgres CDC settings](#postgres-cdc-settings). |

| `skip_tables_with_columns` | postgres | Leave out tables with a column matching one of these patterns. |
| `mask_key` | all | The key for `hmac` masks, normally `${ENV:MASK_KEY}`. |
| `warehouse` | snowflake | From 0.26.0. The warehouse unloads run on; the connection's when omitted. |
| `stage` | snowflake | From 0.26.0. Where unloads go: `{ url, storage_integration, region }` or `{ name }`; the user stage when omitted. See [Snowflake](/docs/sources/snowflake/#where-the-files-go). |
| `max_text_size`, `max_binary_size` | odbc | From 0.27.0. The longest text and binary value a read holds, in bytes; caps every text and binary column. See [ODBC](/docs/sources/odbc/#value-sizes). |
| `max_batch_memory` | odbc | From 0.52.0. The fetch buffer of each table: the most the rows of one fetch hold, such as `"2GB"`; 512 MiB, or less on a small machine, when omitted. It doesn't bound the load's whole memory. See [ODBC](/docs/sources/odbc/#memory). |
| `long_column_threshold` | odbc | From 0.52.0. The buffer per value over which a text or binary column is read value by value; `"4KiB"` when omitted. See [ODBC](/docs/sources/odbc/#value-sizes). |
| `project` | bigquery | From 0.30.0. The project the tables live in; the connection's when omitted. |
| `path` | files | The folder holding the files, relative to the connection. |
| `format` | files | `parquet` (default), `ndjson`, `json` or `csv`. |
| `compression` | files | `auto` (default), `none`, `gzip` or `zstd`. |
| `csv` | files | `{ delimiter, header, quote, null_values }`; defaults `","`, `true`, `'"'`, `[""]`. From 0.54.0, also `escape` (none by default), `quote = false` and `encoding_check` (`true`). See [Quotes and escapes](/docs/sources/files/#quotes-and-escapes). |
| `shape` | files | From 0.27.0. `columns` (default) or `record`: each JSON object or CSV line whole in one `json` column. See [Whole records](/docs/sources/files/#whole-records). |
| `record_column` | files | From 0.27.0. The column `shape = "record"` loads into; `record` when omitted. |
| `partition_columns` | files | Hive `key=value` folders as typed columns, such as `{ dt = "date" }`. |
| `path_columns` | files | From 0.26.0. A path template whose captures load as typed columns, such as `"{region}/{day:date}/*"`. See [Columns from paths](/docs/sources/files/#columns-from-paths). |
| `unmatched_paths` | files | From 0.26.0. `fail` (default) or `skip`: what a file whose path doesn't match `path_columns` does. |
| `order` | files | From 0.54.0. `modified` (default) or `path`: the order a `merge` or `delete_insert` by `replace_key` applies files in, one commit each. See [Merging files](/docs/sources/files/#merging-files). |
| `on_empty` | files | From 0.54.0. `fail` (default) or `skip`: what a load does when the folder exists and holds no files. See [Empty folders](/docs/sources/files/#empty-folders). |
| `copy_to_internal_stage` | files into Snowflake | Upload files no external stage covers to `@~`. Much slower. |
| `[sources.NAME.tables."schema.table"]` | all | Per-table settings. A files source's table is named after the source. |

A source can also set any [table setting](#table-settings), as the default for its tables.

### Postgres CDC settings

A [`postgres_cdc`](/docs/sources/postgres-cdc/) source takes these:

| Key | Default | Meaning |
|-----|---------|---------|
| `kind` | | `postgres_cdc`. |
| `connection` | | A `postgres` connection. |
| `include`, `exclude` | | `schema.table` patterns, as for a [Postgres source](/docs/sources/postgres/#choosing-tables). |
| `cdc_mode` | `merge` | `merge` keeps one row per key; `changelog` appends every change. A files target takes `changelog` only. |
| `deletes` | `soft` | `cdc_mode = "merge"` only: `soft` marks a deleted row with `_sqlload_deleted_at`; `hard` removes it. A [table setting](#table-settings), so a table may override it. |
| `slot` | `sqlload_<source>` | The replication slot. |
| `publication` | `sqlload_<source>` | The publication. SQLLoad creates `sqlload_<source>` when it's missing. |
| `batch_interval` | `10s`, `1m` into files | With [`load --follow`](/docs/guides/postgres-cdc/#keep-streaming): how often it writes what it has read. At least `1s`. |

Column settings (`columns`, `exclude_columns`, `mask` and the rest) work as for other sources. A
captured table takes no `write_strategy`, `cursor_column`, `batch_size` or `state`. `merge`
matches rows on the primary key, and a `unique_key` must lie within it.

## Table settings

Set on a source for all its tables, or in a `[sources.NAME.tables."schema.table"]` entry for one.

| Key | Default | Meaning |
|-----|---------|---------|
| `write_strategy` | required | `append`, `merge`, `delete_insert` or `replace`. From 0.46.0 every table needs one, from its own entry or its source; `plan` refuses a table without it. See [Write strategies](/docs/concepts/write-strategies/). |
| `unique_key` | required for `merge` | A column or list of columns, or `"{primary_key}"` for the primary key the source reports (not for Python, files or Google Sheets sources). From 0.46.0 a `merge` table needs one. See [merge](/docs/concepts/write-strategies/#merge). |
| `on_duplicate_keys` | `dedupe` | From 0.39.0. What `merge` does with rows of one commit that repeat a key: `dedupe` keeps one row per key, `fail` refuses the commit. See [Repeated keys](/docs/concepts/write-strategies/#repeated-keys). |
| `null_keys` | `match` | From 0.51.0. What `merge` does with a NULL in a `unique_key` column, and `delete_insert` in a `replace_key` column: `match` matches it with a NULL, so the row is updated rather than inserted again; `fail` refuses a commit holding one. See [NULLs in keys](/docs/concepts/write-strategies/#nulls-in-keys). |
| `replace_key` | none | From 0.51.0. A column or list of columns whose values `delete_insert` replaces whole: each commit deletes the rows holding a value its rows hold, then inserts them. Not unique. Only for `delete_insert`, and not with a `cursor_column`: each load reads the whole source, or a files source's new and changed files. See [Replacing rows by a key](/docs/concepts/write-strategies/#replacing-rows-by-a-key). |
| `deletes` | none | From 0.54.0. `soft` or `hard`: what `load --sync-deletes` does with the rows of a `merge` table whose key the source no longer holds (Postgres, ODBC, Snowflake and BigQuery sources). `soft` sets `_sqlload_deleted_at`; `hard` removes the row. A `postgres_cdc` source applies captured deletes this way, `soft` by default. See [Rows deleted at the source](/docs/concepts/write-strategies/#rows-deleted-at-the-source). |
| `deletes_from` | none | From 0.54.0. Tables only: `{ table = "audit.deleted_items", cursor_column = "deleted_at" }`, a source table recording deleted keys. Every load appends its new rows to `<table>__sqlload_deletes` and marks the rows they name, as `deletes` says. See [Deletes from a tombstone table](/docs/concepts/write-strategies/#deletes-from-a-tombstone-table). |
| `newest_by` | none | From 0.54.0, replacing `dedup_sort`. A column, or a list compared in order, whose higher value is a row's newer version: `merge` keeps the newest of a commit's rows sharing a key, and never overwrites the table's row with an older one. Without it, the row read last wins. See [Repeated keys](/docs/concepts/write-strategies/#repeated-keys). |
| `cursor_column` | none | The column runs continue from. From 0.51.0, a list such as `["updated_at", "created_at"]` reads the first non-NULL column of each row. See [Cursors](/docs/concepts/cursors/). |
| `cursor_start` | none | Where the first run starts. |
| `lookback` | none | Read this far before the maximum: a duration on a date or timestamp cursor, such as `"2h"`; from 0.52.0, a number of cursor units on an integer cursor, such as `1`. See [Cursors](/docs/concepts/cursors/#fiscal-year-tables). |
| `lookback_from` | `destination` | From 0.26.0. `destination` (the destination's maximum) or `now`: what `lookback` counts back from. See [Reload a window](/docs/guides/reload-a-window/). |
| `lookahead` | none | From 0.26.0. Read only cursor values before now plus this; a date cursor reads up to and including today plus that many days. |
| `append_cursor_inclusive` | `false` | Whether `append` reads from the maximum itself (inserting its rows again) rather than after it. |
| `cursor_bounds` | `parameters` | From 0.47.0, ODBC sources only. `parameters` binds the cursor's bounds as typed parameters; `literals` writes them into the query as ODBC escapes (`{ts '…'}`, `{d '…'}`), for a driver that refuses a bound value. See [Cursor bounds](/docs/sources/odbc/#cursor-bounds). |
| `on_cursor_out_of_range` | `fail` | From 0.53.0, Python tables with a cursor only. What a load does with rows the function returns outside the window it was asked for: `fail` fails the table, naming them and their likely cause; `skip` drops them; `warn` loads them. The load report counts them under `skip` and `warn`. See [Rows outside the window](/docs/concepts/cursors/#rows-outside-the-window). |
| `null_cursor` | `fail` | From 0.51.0. What an incremental read does with source rows whose cursor is NULL: `fail` fails the load when there are any, `include` reads them on every run (`merge` only), `ignore` skips them. See [NULL cursor values](/docs/concepts/cursors/#null-cursor-values). |
| `batch_size` | none | Commit one cursor window at a time: a duration (`"1d"`) or an integer step, or `"none"`. |
| `contract` | `none` | `none` or `enforced`. See [Contracts](/docs/concepts/contracts/). |
| `on_schema_change` | `append_new_columns` | `append_new_columns`, `ignore` or `fail`. |
| `auto_widen` | `false` | Widen inferred columns along `bool` → `int` → `decimal`, `timestamp_ntz` → `timestamp_tz`. |
| `infer_types` | `true` | From 0.54.0. `false` loads every column SQLLoad would infer (files but Parquet, Google Sheets, Python dict rows) as `text`; pinned `columns` keep their types. See [Loading every column as text](/docs/concepts/types/#loading-every-column-as-text). |
| `on_nonfinite` | `keep` | From 0.54.0, Python tables and tables with a `transform` only. `null` loads NaN and infinite floats in dict rows as NULL; `keep` keeps them where the column holds them and fails the table, naming the column and row, where it can't. See [NaN and infinities](/docs/sources/python/#nan-and-infinities). |
| `type_change_rebuild` | `require_confirmation` | `allow`, `require_confirmation` or `deny`. |
| `checks` | none | `{ unique, not_null, min_rows, max_row_drop, warn }`, run on the staged rows before they're published. See [Checks before publish](/docs/concepts/checks/). |
| `constant_columns` | none | The same value in every row, such as `{ tenant_id = "acme" }`, typed by its TOML value or `{ value, type }`. From 0.26.0 on files sources; from 0.37.0 on every source but `postgres_cdc`, and per table, where a table's map replaces its source's. A files source replaces a file column of the same name, and `plan` notes it; every other source fails at `plan` when it already has a column of the name, ignoring case, before anything is written. See [Several tenants in one table](/docs/concepts/write-strategies/#several-tenants-in-one-table). |
| `unnest` | none | From 0.40.0. In a table entry only: the dotted paths of the list fields whose items become rows of child tables, such as `["items", "items.parts"]`, or `"all"`. See [Nested data](/docs/concepts/nested-data/). |
| `flatten` | none | In a table entry only: the dotted paths of the objects whose keys load as `<object>__<key>` columns, such as `["customer", "customer.address"]`, or `"all"`. JSON and NDJSON files default to `"all"` under `compat = "dlt"`. See [Flattening objects](/docs/concepts/nested-data/#flattening-objects). |
| `max_depth` | `1000` | From 0.40.0. In a table entry with `unnest` or `flatten`: how many levels of child tables it makes and objects it flattens at most. |
| `parse` | none | From 0.53.0. In a table entry only: the text columns read as times, by column, such as `{ updated = { timestamp = ["iso", "%m/%d/%Y %H:%M"], tz = "Europe/Paris" } }` or `{ created = "epoch_ms" }`. See [Parsing text into times](/docs/concepts/types/#parsing-text-into-times). |
| `timezone` | none | From 0.53.0. The IANA zone, such as `"Europe/Paris"`, of times without an offset: those a `parse` without its own `tz` reads, and a `cursor_start`, `--start-cursor` or `--end-cursor` on a cursor of times. A Python table's `ctx.cursor_value` and `ctx.cursor_end` arrive in it. UTC when unset. See [Times without an offset](/docs/concepts/cursors/#times-without-an-offset). |
| `naming` | the target's | `snake_case` or `source`. See [naming](/docs/concepts/nested-data/#naming-1). |
| `rename` | none | From 0.53.0. A map of source names to loaded names, such as `{ "Order ID" = "order_ref" }`, or the name a Python function was registered under with `@sl.rename`. See [rename](/docs/concepts/nested-data/#rename). |
| `on_duplicate_names` | `number` | From 0.53.0. `number` or `fail`: what happens when columns load under one name, ignoring case. See [on_duplicate_names](/docs/concepts/nested-data/#on_duplicate_names). |
| `compat` | the target's | From 0.53.0. `sqlload` or `dlt`. See [compat](/docs/concepts/nested-data/#compat). |
| `send` | the target's | From 0.53.0. `at_commit` or `per_batch`. See [Sending rows at commit](/docs/targets/#sending-rows-at-commit). |
| `row_id` | `false` | From 0.40.0. Give every row a unique id, in `_sqlload_row_id`. Always on with `unnest` and under `compat = "dlt"`, where it is `_dlt_id`. |
| `transform` | none | From 0.52.0, files and `google_sheets` sources. The name a Python function was registered under with `@sl.transform` (its own name, or the one given as `@sl.transform("kpis")`) in a module under `python_paths`, run on each file's or range's rows before they load. `plan` fails on a name no function has, or two do. Needs `python_paths` and the `sqlload` Python package. An `sl.http` job takes [`transform=`](/docs/sources/python/#transforming-each-page) instead. See [Transforming each file](/docs/sources/files/#transforming-each-file) and [Transforming each range](/docs/sources/google-sheets/#transforming-each-range). |
| `column_names` | none | From 0.49.0. The columns' names, in order, for data without a header row: CSV and Excel files with `header = false`, and `google_sheets` ranges with `header = false`. The count must match the data's columns. See [Naming headerless columns](/docs/sources/files/#naming-headerless-columns). |

ClickHouse targets also take these, for the tables SQLLoad creates. Other targets refuse them, and
Python tables don't take them. See [Table layout](/docs/targets/clickhouse/#table-layout).

| Key | Default | Meaning |
|-----|---------|---------|
| `engine` | `MergeTree` | The table engine with its arguments, of the `MergeTree` family. |
| `order_by` | the `unique_key`, else unsorted | The sorting key: an expression or a list of them. |
| `partition_by` | none | The partitioning expression, such as `"toYYYYMM(updated_at)"`. |
| `primary_key` | none | A prefix of `order_by`. |
| `table_settings` | none | Table settings by name, such as `{ index_granularity = 4096 }`. |

Only in a table entry:

| Key | Meaning |
|-----|---------|
| `description` | The table's description, which becomes its comment. |
| `name` | The destination table name, overriding `table_name`. |
| `sql` | A query whose rows are the table (snowflake sources from 0.26.0; odbc sources from 0.27.0; bigquery sources from 0.30.0); the entry's key is its name. |
| `columns` | Pinned column types, such as `{ total = "decimal(18,2)" }`. See [Types](/docs/concepts/types/). |
| `mask` | Masked columns: `{ email = "hmac" }` or `"hash"`. |
| `exclude_columns`, `allow_columns`, `destination_path` | As on the source, for this table. |

Python tables take the same settings as decorator arguments, except `lookahead` and
`lookback_from`, which they refuse, plus `allow_empty` and `state`. See
[Python sources](/docs/sources/python/#settings).

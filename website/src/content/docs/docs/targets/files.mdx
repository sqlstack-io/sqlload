---
title: "Parquet files"
description: "Write each table as zstd Parquet files in S3 or a local folder, partitioned by a template."
---

A files target writes each table as Parquet files in its own folder.

```toml
[connections.out]
kind = "filesystem"
root = "out"

[targets.files]
connection = "out"
path = "{source}/{table}/dt={cursor:date}/"
```

| Key | Meaning |
|-----|---------|
| `connection` | An `s3` or `filesystem` connection. |
| `path` | Each table's folder: a template with `{source}`, `{schema}`, `{table}`, and `{cursor}` or `{cursor:date}` to partition by the cursor. Default `{source}/{table}/`. |
| `format` | `parquet`, the only format and the default. |
| `max_footer_reads` | The most Parquet footers `plan` reads for one table's schema. Default 100. |

A source's `destination_path`, or one table's, overrides the target's `path`.

```console
$ sqlload load
Plan ready  1 selected, 1 to load

Loads (1)                                           sqlload load
└── app__orders                                     delete_insert (cursor: updated_at)
    ├── source  postgres  app  public.orders
    ├── files   out/app/orders/  parquet (zstd)  partitions dt={cursor:date}/
    ├── schema  first files, 7 columns
    ├── batch   about every 1 GB, in updated_at order (an index leads with it, NULLs first), between distinct values; each commit replaces its own cursor range
    ├── cursor  updated_at first run, everything
    └── note    each partition written or in the window gets its new files first, then its older files are deleted; not atomic, so a reader in between sees both

✓ Plan complete  1 selected, 1 to load
loaded   out/app/orders/  1,001 rows  0.0s

✓ Completed  1 loaded, 1,001 rows, 0.0s
```

Files targets take `append`, `replace` and `delete_insert`. `merge` needs a table format that
updates rows in place, so `plan` refuses it on a files target.

The table's schema is the footers of the newest load in its newest partition. `sqlload contract
diff --all-files` reads every file's footer to report files whose columns differ. See
[`sqlload contract`](/docs/cli/contract/).

A [`postgres_cdc` source](/docs/sources/postgres-cdc/#into-parquet-files) loads into a files
target as a changelog, adding files with each load.

From 0.27.0 (not released yet), a [files source](/docs/sources/files/) loads into a files target.
SQLLoad reads the source files and writes them out again, with `append`, `replace`, or
`delete_insert` by a partition cursor. Each commit records the source files it loaded in
`_sqlload/loaded/<commit>.json`. Under `append`, the next load skips those files and reads only
new ones. With a partition cursor, `append` reads from the target's newest partition onward, so
a late file added to an older partition isn't loaded. As for other targets, a source file
rewritten in place fails the table until you reload the table with `--reload`, or use
`delete_insert` on a partition cursor. A record counts only while the table still holds its
commit's files: the files of a load that failed and was repaired load again, and the next load
deletes records whose files are gone.

The target folder can't be the source folder, or inside it or around it: a load would delete or
read back its own source files, so `plan` blocks the table.

SQLLoad keeps its bookkeeping for each table under `<table folder>/_sqlload/`: markers for loads in
progress, the run log of `state = "logged"` tables, and the source files a files source's
loads loaded. Run one load at a time per files table.

From 0.27.0 (not released yet), SQLLoad enforces that rule. A load takes a lease on the table, a
file in `_sqlload/lease/`, before it repairs or writes anything. It renews the lease every minute
and releases it when it finishes. While another load holds a live lease, `plan` blocks the table
and `load` refuses it:

```text
the table is being loaded by load 3f9c… (started 2026-11-08 09:00:00 UTC, lease until 2026-11-08 09:10:00 UTC); retry once it finishes
```

A lease lasts 10 minutes, so a load that crashed holds the table until then. The next load
then repairs what it left. Before deleting older files, a load checks that it still holds the
lease. If its lease lapsed, or another load took the table, it stops without deleting them.

## Limitations

- Before 0.27.0, a files source can't load into a files target.
- The lease (from 0.27.0, not released yet) trusts the clocks of the machines that load, and
  needs a store that honours create-only writes, as a local folder and S3 (`If-None-Match: *`) do.
  A load paused for longer than its lease, or an S3-compatible store that ignores that header, can
  still let two loads write one table. With `AWS_CONDITIONAL_PUT=disabled`, loads into S3 fail
  instead.
- `replace` and `delete_insert` write the new files first, then delete the older ones. A reader in
  between sees both, as the plan's `note` says.

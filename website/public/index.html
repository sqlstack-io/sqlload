Load data into your warehouse. Fast.

See the plan before any data moves.

When your files are already in a bucket or folder, the warehouse loads them itself, and no row passes through the loader. Everything else is staged as Parquet and bulk-loaded, not inserted row by row.

The loading framework you keep rebuilding

Hidden state drifts from reality

A stored copy of the schema or the cursor disagrees with the warehouse, and the fix is deleting state you can't see.

Types quietly change

Decimals lose digits, JSON turns into strings, and a stray value becomes a second column.

Rows go the long way round

Files already in a bucket are downloaded, parsed and uploaded again, when the warehouse could copy them itself.

You find out in production

Nothing shows which tables, columns and routes a run will touch until it has touched them.

Plan, apply, load

One sqlload.toml, three commands, and nothing kept outside your warehouse.

02 · Load

Bulk copy, not row inserts

Files in S3 load into Snowflake straight from an external stage. Parquet loads into DuckDB through DuckDB's own reader. Rows are staged as Parquet and copied in bulk.

03 · Stay stateless

The warehouse is the state

Incremental tables continue from the destination's own maximum. The schema is the live table. No local cache, no schema tables to fall out of sync.

Cursors and state →

└── app__orders                merge (unique_key: order_id)

04 · Keep types exact

Declare what matters

Portable types, mapped per warehouse. Pin a column and SQLLoad widens the table in place; check declarations against live tables in CI.

Contracts and schema changes →

# sqlload.toml
[sources.app.tables."public.orders"]
columns = { total = "decimal(18,2)" }

sqlload plan app__orders
└── raw.app__orders            alter table
    └── widen  total decimal(12,2) -> decimal(18,2)  in place

sqlload contract diff
  OK    table:app__orders
0 contract difference(s)
05 · Write sources in Python

APIs without the plumbing

Yield dicts, Arrow data or JSON bytes. HTTP pagination, fan-out, retries and rate limits run in Rust.

Python sources →

import sqlload as sl

shop = sl.source("shop", connection="shop")
api = sl.http(shop, auth=sl.bearer(), rate_limit="10/s")

@shop.table(unique_key="order_id")
def orders(ctx):
    """Orders, one row per order."""
    return api.paginate("/orders", select="$.items",
                        paginator=sl.page_number("page"))
